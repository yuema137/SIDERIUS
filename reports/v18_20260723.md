# V18 split-mode launch plan — 2026-07-23

Companion to `docs/v18_split_run_plan.md` (rev 2). This report is the
operational runbook: background, exact launch commands, sequence,
expected artifacts, monitoring, and the Wave-1 checkpoint. Mirrors the
structure of `reports/v17_20260717.md`.

## 1. Background and goal

V18 explores denoising in **split mode**: the 20 TIDMAD validation files
are partitioned into four DataScope groups (`0-3`, `4-9`, `10-14`,
`15-19`), each explored by an independent loss chain and architecture
chain — 8 chains total. Motivation: per-group specialists over the
frequency-band structure, enabled by the `enable_partial_file_list`
feature (DS1–DS8, branch `feat/enable-partial-file-list`), which
enforces the file restriction at the sample-set builder and sandbox I/O
boundary and pins scope + HealthGate policy per workspace via
`run_invariants_lock.json`.

Everything not scope-related is inherited from V17 unchanged: iteration
topology (20 iterations, 3 rounds), delta gates, budgets, observe-mode
HealthGate YAML, advice files, LLM config, three-branch loss framework.

## 2. Execution topology

Two waves of 4 concurrent chains (host is CPU-dataloader bound at 4):

|---|---|---|---|
| 1 | `v18_loss_04_09`, `v18_arch_04_09` | 4-9 | 4,5,6,7,8,9 |
| 1 | `v18_loss_10_14`, `v18_arch_10_14` | 10-14 | 10,11,12,13,14 |

Sequence:

```
Wave 1 (4 chains in parallel)
  → all four exit markers present
  → automatic summary  (scripts/v18_wave_summary.py)
  → manual operator review
  → operator approval
  → Wave 2 (4 chains in parallel)
```

## 3. Scope / HealthGate contract

- HealthGate policy file: `configs/health_checks_baseline_observe_mode.yaml`
  (observe-only every-round), unchanged on disk. Each chain materializes
  its own `{workspace}/health_checks_effective.yaml` with the run-level
  monitored-file override = **every file in its scope** (operator
  decision, rev 2 — no representative-file selection).
- Scope + gate policy are pinned per workspace by
  `run_invariants_lock.json`; `--auto_resume` validates the lock, and any
  conflicting re-invocation fails at startup before any LLM/training.
- Sampling is snapshot-only under a partial scope (operator config
  errors at startup; LLM plans normalize with recorded provenance), so
  every monitored file has a denoised output every round by construction.

## 4. Seed policy

All 8 chains are **seedless cold starts** (PR #126). The V17 full-scope
seeds are rejected by ingress validation under any partial scope — this
rejection is designed behavior. No seed files are passed.

## 5. Preflight checklist (per wave)

1. `feat/enable-partial-file-list` checked out (or merged), Checkpoint DS
   Gates recorded (Gate 1 PASS 2026-07-23; Gate 2 per design doc).
2. `nvidia-smi` shows the H100 free enough for 4 × 12 GB worst case.
3. `df -h /workspace/DATA` has headroom (denoised H5s are cleaned per
   round via `--cleanup_denoised`, emitted by the chain wrapper).
4. Dry-run each command (`--dry-run`) — banner must show the intended
   `Data scope` and the FULL monitored list. Done 2026-07-23 for all
   four Wave-1 commands: 20 iterations walked, no side effects.
5. No pre-existing workspace of the same name (or accept auto-resume
   semantics on an interrupted prior attempt).

## 6. Exact Wave-1 launch commands

Environment (this box): repo `/workspace/REPO/SIDERIUS`, venv `.venv`,
data root `/workspace/DATA/SIDERIUS_DATA`.

```bash
REPO=/workspace/REPO/SIDERIUS
WS_ROOT=/workspace/DATA/SIDERIUS_DATA
DATE=$(date +%Y%m%d_%H%M)
cd "$REPO"

launch_v18 () {  # $1 flavor(loss|arch)  $2 scope  $3 files  $4 tag
  local RUN="v18_$1_$4"
  screen -L -Logfile "$WS_ROOT/${RUN}_${DATE}.log" -dmS "siderius-$RUN" bash -lc "
    set -euo pipefail
    cd '$REPO'
    .venv/bin/python -c 'import torch; assert torch.cuda.is_available()'
    set +e
    bash sdsc_submission_scripts/run_chain.sh \\
      --mode lilab \\
      --workspace '$WS_ROOT/$RUN' \\
      --run_name '$RUN' \\
      --num_iterations 20 \\
      --auto_resume \\
      --max_rounds 3 \\
      --max_epochs 1 \\
      --data_scope '$2' \\
      --health_gate_files '$3' \\
      --skip_formal_min_delta 0.0 \\
      --bypass_formal_time_budget_min_delta 0.5 \\
      --trial_time_budget_minutes 12 \\
      --formal_time_budget_minutes 120 \\
      --trial_vram_budget_gb 10 \\
      --formal_vram_budget_gb 12 \\
      --formal_strategy snapshot \\
      --formal_round_strategy inherit_best_trial \\
      --exploration_mode explore \\
      --ml_lit_review_enabled \\
      --llm_config llm_configs/openai_tiered_v1.json \\
      --advice 'advice/workflow/v17_$1_explorer.json' \\
      --health_checks_config configs/health_checks_baseline_observe_mode.yaml
    status=\$?
    set -e
    printf 'EXIT=%s\\n' \"\$status\" > '/tmp/${RUN}.exit'
    exit \"\$status\"
  "
  screen -ls | grep -F "siderius-$RUN"
}

launch_v18 loss "4-9"   "4,5,6,7,8,9"    04_09
sleep 90   # stagger startups (V17 practice: avoid simultaneous CUDA init + LLM warmup)
launch_v18 arch "4-9"   "4,5,6,7,8,9"    04_09
sleep 90
launch_v18 loss "10-14" "10,11,12,13,14" 10_14
sleep 90
launch_v18 arch "10-14" "10,11,12,13,14" 10_14
```

Wave 2 (ONLY after checkpoint approval): the same `launch_v18` calls with
`loss|arch "0-3" "0,1,2,3" 00_03` and
`loss|arch "15-19" "15,16,17,18,19" 15_19`.

## 7. Expected output / artifacts per chain

At `{WS_ROOT}/{run_name}/`:

- `run_invariants_lock.json` — resolved scope + `health_gate_enabled` +
  effective-config sha256, written at iteration 1, validated by every
  later iteration/resume.
- `health_checks_effective.yaml` — materialized policy with the
  all-in-scope monitored list (sha pinned by the lock).
- `iter_001/ … iter_020/` — per-iteration `manifest.json`
  (status ∈ completed | no_records | failed, best raw/valid scores,
  `resolved_data_scope` stamp), `iteration_001/{model}/` tuner artifacts
  (`run_output_*.json`, `summary_*.json`, records/), workflow summary.
- `plugins/iter_NNN/` — promoted model/loss plugins for chain resume.
- `.token_run_id`, `token_usage.jsonl` — token audit.
- `/tmp/{run_name}.exit` — exit marker; `{WS_ROOT}/{run_name}_{DATE}.log`
  — full log.

Expected behavior notes: iteration 1 is a cold start (deterministic
"no prior evidence" interpretation, no LLM call for interp); every
record/manifest carries the group's `resolved_data_scope`; `[DATASCOPE]`
banners appear at workflow pre-flight and each tuner startup; the LLM
sees the `[DATA SCOPE]` prompt block and the fixed-params snapshot-only
disclosure; occasional `strategy_normalization_reason=
"partial_data_scope"` provenance is normal, frequent occurrences are not
(disclosure should make them rare — Gate 1 observed zero).

## 8. Monitoring

```bash
screen -ls | grep siderius-v18
tail -60 $WS_ROOT/v18_loss_04_09_${DATE}.log     # etc. per chain
nvidia-smi
df -h /workspace/DATA
for r in v18_loss_04_09 v18_arch_04_09 v18_loss_10_14 v18_arch_10_14; do
  cat /tmp/$r.exit 2>/dev/null || echo "$r still running"; done
# Interim scope-safe peek (read-only, safe on live chains):
.venv/bin/python scripts/v18_wave_summary.py $WS_ROOT/v18_loss_04_09 \
  $WS_ROOT/v18_arch_04_09 $WS_ROOT/v18_loss_10_14 $WS_ROOT/v18_arch_10_14
```

Stop conditions per chain (same as V17): consecutive-failure brake
(3 failed iter manifests → `.chain_halted`), operator `screen -S … quit`.
Resume: rerun the same `launch_v18` line — `--auto_resume` +
`run_invariants_lock.json` validation continue safely.

## 9. Wave-1 checkpoint (mandatory before Wave 2)

When all four `/tmp/v18_*.exit` markers exist:

1. Run the summary command above; save output to
   `reports/v18_wave1_summary_{date}.md`.
2. Review: best raw vs valid scores per chain, collapse statistics,
   gate-action distribution, ABNORMAL section must be empty (or
   explained), iteration completion counts.
3. Operator approves → launch Wave 2. No approval → no Wave 2.

## 10. Analysis contract

- Aggregate scalars comparable only WITHIN a group (scope-homogeneity);
  cross-group analysis uses per-file vectors (anchor-normalized,
  globally comparable).
- The 20-row score tables render out-of-scope files as `None` rows —
  identical to historical sparse-sampling runs; no reporting changes
  needed (audit in `docs/v18_split_run_plan.md` §Configuration audit).

## 11. Runtime and cost estimate

Per chain ≈ V17 per-chain wall time or less (formal eval covers 4–6
files instead of 20); 20 iterations × 3 rounds with 12/120-min budgets.
LLM cost per chain ≈ V17 (same call topology; ~128k tokens per
iteration observed in Gate 1) → plan for the same order as one V17
campaign per wave.

## 12. Non-goals

- No cross-group incumbent (scope-keyed incumbent is a V18 design item,
  `docs/design/v18_priorities.md` §3.4).
- No changes to scoring semantics, anchor map, advice files, or
  HealthGate YAMLs.
- No seeding, no Phase-1 scoped baselines in this launch (optional
  later via `run_comparison.py --data_scope`).
