# Execute-tools integration tests

These tests check that a real training subprocess receives the declared data,
model cardinality and input dtype. They also exercise a tiny synthetic training
loop. The files are generated by the tests; no scientific dataset or API key is
needed.

From a checkout with `uv sync --group dev --frozen` completed, run the CPU tests:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv/bin/python -m pytest tests/integration/execute_tools/ -q
```

A successful run reports passing CPU tests and skips the optional CUDA
checkpoint-memory tests. Use `TMPDIR` and `--basetemp` to select scratch storage
when needed. Integration tests run locally; unit-test CI does not run this directory.

The subprocess fixture writes a task manifest and a scope file describing which
synthetic rows the child should read. Its digest lets the child check that the
scope arrived unchanged. See the [subprocess contract](subprocess-contract.md)
for fixture ownership and assertions, or the [integration map](../README.md)
for other integration routes.
