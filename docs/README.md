# SIDERIUS documentation

SIDERIUS connects a task's scientific definitions to a controlled research
workflow. Choose a route below, then follow the next directory's guide.
READMEs explain where to start; linked technical references describe exact
interfaces and behavior.

| Your next step | Start here |
| --- | --- |
| Install and try a small offline example | [Getting started](getting-started/README.md) |
| Understand tasks, scores and recorded results | [Concepts](concepts/README.md) |
| Define a task or operate a run | [Guides](guides/README.md) |
| Look up a configuration field or execution contract | [Reference](reference/README.md) |
| Change framework source | [Contributor references](agent-reference/README.md) |
| Find tests and qualification procedures | [Testing](testing/README.md) and [Gates](gates/README.md) |
| Understand an earlier decision | [Design history](design/README.md) and [audits](audit/README.md) |

For real scientific data, use the companion
[siderius-exp tutorials](https://github.com/yuema137/siderius-exp/tree/main/tutorials).
They are simplified workflow demonstrations. Scientific configurations and
historical results belong to that repository; the framework's
[examples](../examples/README.md) use synthetic data.

The [repository map](repository-map.md) identifies source owners and the
framework/experiment boundary. [CLAUDE.md](../CLAUDE.md) owns repository rules.
[Release notes](releases/README.md) and [figure provenance](assets/README.md)
provide dated context; neither substitutes for task qualification.
