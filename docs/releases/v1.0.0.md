# SIDERIUS v1.0.0

This historical entry describes the framework at tag `v1.0.0`, dated
2026-10-08, targeting commit
[`cdf4487fc23525d78155f4758ccda0b22b91eb28`](https://github.com/yuema137/SIDERIUS/commit/cdf4487fc23525d78155f4758ccda0b22b91eb28).
The changes below summarize merged history from `v0.3.0` to that tag; they
are not a description of current `master` or an exhaustive commit inventory.

The tagged framework combines LLM-driven model development with deterministic
data access, execution, scoring, validity checks and provenance. Scientific
tasks and experiment settings remain in external projects. Professional and
Assistant describe ways of working with a coding agent, not runtime modes.

## Changes

### Setup and external orchestration

- Add optional standard-run setup inspection and HTML reports, including task
  checks, environment settings, semantic review or an explicit skip receipt,
  and a reviewed launch that checks the selected inputs. Direct launch remains
  available. Initial setup review supports a new workspace and one standard
  workflow iteration (#614, #669).
- Add external orchestration project assembly and an opt-in Linux workspace
  sandbox using bubblewrap. The caller still supplies scientific settings and
  the command to execute; existing workflows do not automatically use this
  sandbox (#669).
- Document coding-agent setup through Professional and Assistant routes,
  including a one-sentence task brief and external-project ownership
  (#674, #675).

### Execution and evidence

- Retain runtime verification across training epochs, including short epochs,
  and account for training cleanup time (#603).
- Align inference measurement with production task execution and carry
  explicit task bindings through executable runtime replay (#620, #630).
  Replay execution requires a task-bound probe configuration and output
  directory; metadata and planning modes remain read-only.
- Add opt-in protected native GPU execution with measurement, admission,
  observation and lifecycle evidence. The selected policy is carried through
  launch and run invariants; it does not introduce a mandatory global GPU
  protection gate (#669).
- Add explicitly selected runtime verifier providers with source and assembly
  identities. Omitting selection retains the native verifier; an invalid
  explicit selection does not silently fall back (#669).
- Require independent formal-result evidence, in agreement with stored
  authority, before including results in scientific aggregation (#611).

### Distribution and configuration guidance

- Add explicitly selected, versioned prompt rendering providers. Composition
  pins provider source/template, boundary-map and framework assembly identities
  into the semantic fingerprint; omission retains native rendering. Separately,
  expose caller-selected Data Analysis preparation recovery policies (#602).
- Honor explicit LLM retry limits for literature main/search and tuner reflector
  routes, preserving omitted versus explicit-null settings through setup review
  and launch snapshots. These are transport attempt limits, not content-repair
  or whole-workflow limits (`28e7039d2`, `aa1a83706`, `7d0d32142`; #669).
- Set package metadata to `1.0.0` and distinguish the inexpensive Luna flow-check
  configuration from research, custom and historical experiment configurations
  (#669).
- Add MIT licensing for original contributions and third-party notices. The
  combined distribution declares `MIT AND CC-BY-4.0`; this does not apply both
  licenses indiscriminately to every file (#647).
