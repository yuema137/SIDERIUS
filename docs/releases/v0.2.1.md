# SIDERIUS v0.2.1

This patch release retains the framework/task boundary and adds an explicit,
task-generic training allocation policy. Existing fixed-epoch callers keep
that behavior unless they opt in.

## Changes

- Retain HDF5 dataset handles with bounded raw-chunk caching, preserving exact
  selections and dtypes while avoiding repeated decompression on small reads.
- Include DataLoader wait in training/validation timing; distinguish normalized
  rates from actual verification duration. Generic inference now records its
  real workload, execution time and memory evidence.
- Expose early training-budget diagnostics without inventing missing costs.
- Opt in to cooperative time/cap stopping with an explicit downstream reserve.
  No scientific early stopping or best-validation weight restoration; keep
  last completed weights. Record proposed versus completed epochs and costs.
- Include continuous-output proposer contract rendering (#536) and updated
  orchestrator documentation/qualification guidance (#533).

## Limits and usage

The reserve is an operator allowance, not a measured downstream guarantee.
Without a killing watchdog, a single unexpectedly slow epoch can overrun;
reaching an explicit epoch cap does not establish convergence. No model, batch,
portion, validation cadence, objective or scientific score is automatically
changed to fill unused time or VRAM.

See [cooperative training](../reference/cooperative-training-budget.md) and
[HDF5 reader](../reference/hdf5-read-cache.md). Real tasks, data, credentials,
campaign settings and qualification receipts remain external to this package.
Release publication is gated on PR CI/review and external workflow qualification;
preparing these notes does not launch an experiment.
