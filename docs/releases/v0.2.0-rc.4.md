# SIDERIUS v0.2.0-rc.4

This is an immutable prerelease of the task-generic SIDERIUS framework. It
identifies the Python distribution as `0.2.0rc4` and records synchronized
lockfile metadata. External qualification remains pending; this is not a
stable release and does not claim scientific performance.

## Scope

Compared with `v0.2.0-rc.3`, this candidate:

- admits generated-model construction only after a bounded candidate-memory
  estimate satisfies the existing generic resource budget;
- separates short human-facing README landing pages from detailed agent-facing
  contracts, while retaining CI checks for both documentation surfaces;
- documents the public config-format, denoising-score and paper-resolver skill
  contracts;
- makes malformed paper-resolver cache inputs return the standard error
  envelope before network access; and
- removes stale TIDMAD and model-family assumptions from generic config-format
  planner guidance, leaving scientific and resource validity with the resolved
  task contracts and execution validators.

The documentation and planner changes do not create a second execution
authority. Public wrapper shapes remain stable, and the runtime fixes are
task-neutral rather than branches for a named dataset or campaign.

This candidate adds no task, dataset, campaign, scientific threshold, metric,
Health policy, retry, retention or watchdog treatment.

## Qualification status

The paired `siderius-exp` revision, fresh external-task workflow evidence,
remaining issue closeout and stable-release acceptance gates are still
pending. This prerelease must not be treated as stable or as evidence that a
scientific campaign is ready to launch.

## Release boundary

This artifact contains no dataset, workspace, credential, real-task package,
campaign state, scientific result or `.structured-coding` asset. Consumers
must provide task data, workspaces, credentials and workflow configuration
explicitly outside the package.
